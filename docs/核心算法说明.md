## 一、取数链路：从「驱动浏览器」到「纯 HTTP」

### 1.1 认识转折点

最初 Win 版也是驱动浏览器的（用 CDP 协议控制 Edge），
和 CampusDesk 用 WKWebView 是同一个思路。

**后来发现一件事**：ManageBac 的页面**全是服务端渲染的 HTML**，
登录也只是**普通表单 POST**，没有任何 JS 加密、没有指纹校验、
没有需要靠 JS 才能拿到的数据。

**这个发现直接改变了架构。**

### 1.2 实测对照

| 方案 | 耗时 | 说明 |
|---|---|---|
| 浏览器逐页读 | **98 秒** | 要等页面加载、等 JS 执行、等 DOM 稳定 |
| 纯 HTTP 串行 | 60 秒 | 网络往返时间累加 |
| 纯 HTTP 并行 3 线程 | **20.7 秒** | 见下 |

### 1.3 核心代码

```python
# 关键点 1：登录用 NoRedirect，把「302」当成成功信号
opener = urllib.request.build_opener(HTTPCookieProcessor(cookie_jar),
    NoRedirect(),          #  不要自动跟随重定向
)

# 关键点 2：POST /sessions，字段名照抄页面表单
data = urllib.parse.urlencode({
    "authenticity_token": token,     # 从登录页 HTML 里挖出来的
    "login": account,
    "password": password,
    "remember_me": "1",              #  必须！否则 Cookie 是会话级
    "commit": "Sign in",
}).encode()

resp = opener.open(req)
# HTTPError 302 = 登录成功（被重定向到首页）
```

** 两个容易漏的点**：

1. **`remember_me=1` 不能省**
   实测：勾了之后 Cookie 带 `expires`（约 30 天持久），
   不勾则是会话 Cookie（关掉就没了）。

2. **`authenticity_token` 每次登录都要重新取**
   它是 Rails 的 CSRF 令牌，从登录页 HTML 里用正则挖：
   ```python
   m = re.search(r'name="authenticity_token"[^>]*value="([^"]+)"', html)
   ```

### 1.4 用结果判断登录态，而不是提前探测

**这是最大的单点性能优化。**

原来的实现：抓详情页前先调 `check_login()` 验证会话 —
而 `check_login()` 会 GET 一整个 **476 KB 的首页**。

**但我们要抓的本来就是一个需要登录的页面** ——
直接请求它，被踢到登录页就说明失效了。**根本不需要额外探测。**

```python
#  慢：先探测（多一次 476 KB 请求，实测 1294 ms）
if session.check_login():
    html = fetch_detail_page(url)

#  快：直接请求，从结果判断（1 ms 装载 + 一次请求）
session.open(verify=False)        # 只装载 Cookie，不发请求
html = fetch_detail_page(url)
if looks_like_login_page(html):
    relogin()
    html = fetch_detail_page(url)  # 重试一次
```

```python
def looks_like_login_page(html: str) -> bool:
    """从内容判断是不是登录页（比额外探测快得多）"""
    head = html[:8000]
    if "session_form" in head:
        return True
    if re.search(r'<input[^>]+name=["\']password["\']', head):
        return True
    low = html.lower()
    return "fusion" not in low and "managebac" not in low
```

**效果：`open()` 1294 ms → 1 ms。**

> ** 设计原则（推广到任何平台）**：
> 「探测」类函数不该有重副作用。
> 问一句「登录还有效吗」不应该启动浏览器、也不该拉一个 476 KB 的页面。
> 让**真正要用的那次请求**去暴露问题，失败再补救。

### 1.5 并行抓取

```python
def _fetch_courses_parallel(courses, workers: int = 3) -> list[Task]:
    """
     workers 保守设为 3 —— 并发太高会触发站点限速（429）。
    """
    from concurrent.futures import ThreadPoolExecutor, as_completed

    def one(course):
        #  每个线程**各自的** HttpSession（独立 Cookie jar），无竞态
        s = httpclient.HttpSession(auto_login_on_demand=False)
        s.open(verify=False)
        if httpclient.cooldown_remaining() > 0:
            return []                      # 已冷却 → 不再发请求
        ...  # 抓主页 / core_tasks / units
        if s.rate_limited:
            return []                      # 被限速 → 放弃

    with ThreadPoolExecutor(max_workers=workers) as pool:
        futs = [pool.submit(one, c) for c in courses]
        for f in as_completed(futs):
            result.extend(f.result())
```

** 为什么必须每个线程一个 Session**：
早期版本共用一个 `HttpSession`，结果 Cookie 并发写文件时
`Permission denied`（Windows 上尤其明显）。

**修法**（两层）：
1. 每个线程独立 Session
2. `save_cookies()` 加全局 `threading.Lock` + 唯一临时名（`{pid}.{tid}`）
   + `PermissionError` 重试 + 10 分钟节流

### 1.6 提速历程汇总

```
浏览器逐页         98.0 s
  ↓ 改纯 HTTP 串行
HTTP 串行          60.0 s   （消除了页面加载和 JS 执行）
  ↓ 加并行（6 → 3 线程）
HTTP 并行 3 线程   20.7 s   （网络往返时间重叠）
  ↓ 去掉多余的登录探测
最终              ~20 s    （且详情页 1.9s → 1ms）
```

## 二、会话存活判断：为什么「有 token」不等于「能用」

### 2.1 踩过的坑

**第一版实现「2.2 秒就报告续期成功」，但一用就 401。**

**根因**：浏览器 `localStorage` 里存的是**上次登录留下的旧 token**。
代码把它读出来，看到「有 token」就以为成功了 ——
实际上那个 token 早就过期了。

**这个坑很隐蔽**，因为：
- 读 token 这一步确实成功了（没报错）
- token 格式看起来也正常
- 只有真正拿去用的时候才发现不行

### 2.2 解法：解码 JWT 检查 `exp`

```python
def jwt_expired(token: str, margin: int = 3600) -> bool:
    """判断 JWT 是否过期（留 margin 秒的提前量）

     不是 JWT / 解析失败 → 当作过期（保守）
     没有 exp 字段 → 当作有效（有些 token 不写 exp）
    """
    parts = (token or "").split(".")
    if len(parts) < 2:
        return True

    # base64url 解码 payload（要补 padding）
    payload = parts[1] + "=" * (-len(parts[1]) % 4)
    try:
        data = json.loads(base64.urlsafe_b64decode(payload).decode("utf-8"))
    except Exception:
        return True

    exp = data.get("exp")
    if not exp:
        return False                    # 没有 exp 就不判断
    return time.time() >= (float(exp) - margin)
```

**Swift 等价实现**：

```swift
func jwtExpired(_ token: String, margin: TimeInterval = 3600) -> Bool {
    let parts = token.split(separator: ".")
    guard parts.count >= 2 else { return true }

    var b64 = String(parts[1])
        .replacingOccurrences(of: "-", with: "+")
        .replacingOccurrences(of: "_", with: "/")
    while b64.count % 4 != 0 { b64 += "=" }

    guard let data = Data(base64Encoded: b64),
          let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any]
    else { return true }

    guard let exp = json["exp"] as? TimeInterval else { return false }
    return Date().timeIntervalSince1970 >= (exp - margin)
}
```

### 2.3  过期还要「先清掉旧会话」

光判断过期是不够的 —— **还要把旧的清掉再重新登录**。

**为什么**：如果不清，页面会因为 localStorage 里有 token
而**看起来已经是登录状态**，于是：
- 可能不显示登录表单 → 填表失败
- 或者直接跳转走 → 读不到新 token

```python
if jwt_expired(token):
    clear_session()          #  必须！清 localStorage
    login_from_scratch()     # 这才是真的重新登录
```

### 2.4  另一个坑：`status == 0` 不代表失败

课表接口（`api.seiue.com`）的探测请求里，
**`status == 0` 表示「请求根本没发出去」**（连接问题、超时等），
**不是**「token 失效」。

```python
def schedule_token_ok() -> bool:
    try:
        r = probe(very_small_range)     # start=2000-01-01, end=2000-01-02
    except Exception:
        return True                     #  网络问题 → 保守认为还有效
    if r.status == 401:
        return False
    if r.status == 0:                   #  请求没发出去
        return True                     # 保守
    return True
```

> ** 设计原则**：**探测失败要保守返回**。
> 宁可误判为「还有效」（让后续请求自己暴露问题），
> 也别贸然触发重新登录（可能累计失败次数 → 锁号）。

## 三、限速保护：识别 429 并全局冷却

### 3.1 为什么 429 特别危险

**429（Too Many Requests）最危险的地方在于：它容易被误判成「没登录」。**

如果代码这样写：
```python
if not check_login():
    relogin()        # ← 灾难
```
那么被限速时会去重新登录 → 登录也失败 → 又触发重试 →
**越试越糟，最终账号被锁**（连续 5 次失败锁定）。

**实测**：Win 版连着跑 7 轮抓取后触发了 429，
返回的 body 只有 **32 字节**。

### 3.2 全局冷却机制

```python
# httpclient.py
COOLDOWN_SEC = 240                  # 4 分钟

_cooldown_until: float = 0.0
_cooldown_reason: str = ""

def set_cooldown(seconds: float = COOLDOWN_SEC, reason: str = "429") -> None:
    global _cooldown_until, _cooldown_reason
    _cooldown_until = time.time() + seconds
    _cooldown_reason = reason
    _persist()                      #  落盘，重启后依然有效

def cooldown_remaining() -> float:
    return max(0.0, _cooldown_until - time.time())
```

**触发点**（实测确认的 3 处）：
```python
set_cooldown(COOLDOWN_SEC, "登录时被限速")     # 登录响应 429
set_cooldown(COOLDOWN_SEC)                    # 普通请求 429
set_cooldown(60, "抓取返回 0 任务")            # 疑似被软限速
```

### 3.3  战斗规则：冷却期内什么都不做

| 行为 | 冷却期内 |
|---|---|
| 发请求 |  绝对禁止 |
| 自动登录 |  **也禁止**（登录请求同样是请求） |
| 补抓/重试 |  禁止 |
| 保留旧缓存 |  显示上次数据，界面说明原因 |
| 下次刷新时间 |  往后推到 `now + min(cooldown + 5, 300)` 秒 |

```python
# pipeline.py
cd = httpclient.cooldown_remaining()
if cd > 0:
    log.info("站点冷却中（还剩 %.0f 秒），本轮跳过抓取", cd)
    mark_status("error", f"站点限速中，{int(cd)} 秒后自动重试")
    _state["next_run_ts"] = time.time() + min(cd + 5, 300)
    return
```

### 3.4 会话状态判定（三态，不是两态）

```python
def check_login(self) -> bool:
    """ 关键：429 要返回 True（保守认为有效），
       绝不能返回 False —— 那会触发重新登录，酿成锁号。"""
    try:
        r = self._get("/student/home")
    except HTTPError as e:
        if e.code == 429:
            self.rate_limited = True
            set_cooldown(COOLDOWN_SEC)
            return True                     # ←  不是 False！
        if e.code in (301, 302, 303):
            return False                    # 真的没登录
        raise
    return True
```

**Swift 等价（用枚举表达三态，比布尔清晰）**：

```swift
enum SessionState {
    case valid
    case expired          // 302 → /login，需要重新登录
    case rateLimited      // 429，需要等待（绝对不要重新登录）
    case unknown          // 网络问题，保守当作有效
}

func checkSession() async -> SessionState {
    do {
        let (_, resp) = try await session.data(from: homeURL)
        guard let http = resp as? HTTPURLResponse else { return .unknown }
        switch http.statusCode {
        case 429:
            await rateLimiter.noteRateLimited()
            return .rateLimited
        case 302, 303:
            let loc = http.value(forHTTPHeaderField: "Location") ?? ""
            return loc.contains("/login") ? .expired : .valid
        case 200: return .valid
        default:  return .unknown
        }
    } catch {
        return .unknown    //  网络错误保守处理
    }
}
```

### 3.5 并发数为什么是 3 而不是 6

**实测**：6 线程跑 7 轮后触发 429；降到 **3 线程**后再没触发过。

**保守是有道理的**：
- 抓 9 门课 × 每门 3 个请求 = 27 个请求
- 3 线程大约 20 秒完成，已经够快
- 而 429 的代价是「4 分钟完全不能动」+ 可能锁号
- **显然不值得为了省 5 秒去冒险**

## 四、登录重试：指数退避与防锁号

### 4.1 锁号机制（踩坑换来的）

**ManageBac 的规则**：
> 连续 **5 次**登录失败 → 账号被临时锁定。
> 而且**每次失败都会重置锁定计时器** —— 越试锁得越久。

**症状**（很容易误判成风控）：
- 表单填得完全正确
- `POST /sessions` 返回 **200**（不是失败）
- **不下发任何 Cookie**，`document.cookie` 为空
- `.login-flash` 容器**是空的**（没有可见错误提示）
- 2 秒后跳回 `/login`
- `navigator.webdriver == false`（不是风控）

** 错误提示藏在别的地方**：
```html
<div class='alert alert-dismissible alert-danger' role='alert'>
  <p class='alert-heading h6'>Error.</p>
  <div class='alert-content'>If your account exists it has been temporarily
  locked due to 5 consecutive failed login attempts. ...</div>
</div>
```

** 判定方法（这个很重要）**：
不要只看「关键词存在」就下结论 —— 要在**干净页面**上做对照：
```
干净登录页     ："temporarily locked" 出现 0 次
提交后页面     ："temporarily locked" 出现 1 次
→ 是真实错误
```

### 4.2 指数退避

```python
def _backoff_ok(key: str) -> bool:
    """现在可以尝试登录吗？（不能则返回 False）"""
    st = _load()
    rec = st.get(key) or {}
    fails = int(rec.get("fails", 0))
    last = float(rec.get("last", 0))

    #  失败 0 次 → 10 分钟；之后每次翻倍；封顶 1 小时
    gap = 600 if fails == 0 else min(600 * (2 ** min(fails, 6)), 3600)
    return (time.time() - last) >= gap


def _record_result(key: str, ok: bool, msg: str = "") -> None:
    st = _load()
    rec = st.get(key) or {}
    rec["last"] = time.time()
    rec["fails"] = 0 if ok else int(rec.get("fails", 0)) + 1
    rec["msg"] = msg[:200]
    st[key] = rec
    _save(st)               # → data/autologin.json
```

**退避序列**：

| 失败次数 | 等待时间 |
|---|---|
| 0 | 10 分钟 |
| 1 | 20 分钟 |
| 2 | 40 分钟 |
| 3 | 80 分钟 |
| 4 | 160 分钟 |
| 5+ | **60 分钟**（封顶） |

### 4.3  识别到「锁定/密码错」立刻停

**这是防锁号最关键的规则**：

```python
def renew_managebac() -> bool:
    if not _backoff_ok("mb"):
        return False                    # 退避期内，不试

    _running.add("mb")
    try:
        err = attempt_login()
    finally:
        _running.discard("mb")

    if err is None:
        _record_result("mb", True)
        return True

    #  遇到这两种错误：立刻停，绝不换方式重试
    if is_locked(err) or is_bad_credentials(err):
        _record_result("mb", False, err)
        log.warning("登录被拒绝（%s），已停止重试", err)
        return False                    # ← 绝不重试！

    # 其他错误（网络等）可以退避后重试
    _record_result("mb", False, err)
    return False
```

**为什么「不换方式重试」很重要**：
早期版本逻辑是「无头失败 → 换成有头再试 → 再失败就弹窗」。
结果遇到锁定错误时，**一次失败变成了 3 次失败**，
锁得更久。

**正确做法**：识别到锁定/密码错 → **立刻停，一次性把结果告诉用户**。

### 4.4 同一时刻只允许一个登录流程

```python
_running: set[str] = set()

def renew_managebac() -> bool:
    if "mb" in _running:
        return False        # 已有登录在进行，别叠
    ...
```

**为什么需要**：界面上的「修复」按钮可能被连点，
或者 pipeline 和界面同时触发 —— 并发登录既浪费又危险。

### 4.5 兜底：自动失败就弹窗，但**预填好**

用户的原话：
> 「要么就弹出网页让我登录，最好是你自己解决。」

所以：

```python
def _schedule_login_browser() -> bool:
    """无头登录失败 → 启动**可见**窗口，账号密码**预先填好**"""
    launch_browser(headless=False,         #  可见
        fill_credentials=True,  #  预填，用户只需点一下
        wait_manual=True,       # 最多等 5 分钟
        timeout=300,
    )
```

**用户只需要点一次「登录」按钮**，不用自己找网页、不用敲密码。

<a name="五"></a>
## 五、详情页预取：优先级排序与串行调度

### 5.1 问题定义

实测（`diag_detail_speed.py`）：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| `open()` 装载 Cookie | 1 ms | 优化前 1294 ms，已解决 |
| **请求详情页 HTML** | **1221 ms** |  真正的瓶颈（175 KB 页面） |
| BeautifulSoup 解析 | 228 ms | |
| 写缓存 | 4 ms | |
| **合计** | **~1450 ms** | |

**这 1.2 秒的网络延迟消除不掉**（服务器就那么慢），
**但可以提前做掉** —— 在用户点开之前就抓好。

### 5.2 优先级排序

```python
def _priority(task) -> tuple:
    """排序：越靠前越该先预取

     顺序设计：
      1. 未完成的排前面（完成的用户基本不会点开看）
      2. 3 天内的排最前（最急）
      3. 有附件的排前面（有附件的才需要展开下载）
      4. 天数越小越前
    """
    days = task.days_left if task.days_left is not None else 999
    urgent = 0 if (days is not None and -999 < days <= 3) else 1
    return (task.completed, urgent, not task.has_attachment, days)
```

**Swift 等价**：
```swift
func prefetchPriority(_ t: Task) -> (Int, Int, Int, Int) {
    let days = t.daysLeft ?? 999
    return (t.completed ? 1 : 0,
        days <= 3 ? 0 : 1,
        t.hasAttachment ? 0 : 1,
        days
    )
}
```

### 5.3  必须串行 + 间隔，绝不能并行

**这是最容易做错的地方**。

详情页请求比列表页**重得多**（175 KB vs 几十 KB）。
列表页可以 3 线程并行，但**详情页必须串行**：

```python
MAX_PREFETCH = 16          # 一次最多 16 个
GAP_SEC = 1.2              # 每个之间间隔 1.2 秒
BUDGET_SEC = 150           # 总预算 150 秒，超时停
MIN_INTERVAL_SEC = 10 * 60 # 10 分钟内不重复预取

def prefetch_all(tasks, max_n=MAX_PREFETCH, gap=GAP_SEC, budget=BUDGET_SEC):
    batch = sorted([t for t in tasks if not t.completed and not _is_cached(t.url)],
        key=_priority,
    )[:max_n]

    t0 = time.time()
    for i, task in enumerate(batch):
        if time.time() - t0 > budget:
            log.info("预取超时预算，停止")
            break
        if httpclient.cooldown_remaining() > 0:
            log.info("站点冷却中，停止预取")
            break

        try:
            taskdetail.fetch(task.url)
        except Exception as e:
            log.debug("预取失败：%s", e)

        if i < len(batch) - 1:
            time.sleep(gap)         #  间隔，不是连续发
```

### 5.4 三个保护

| 保护 | 值 | 原因 |
|---|---|---|
| 冷却中不跑 | `cooldown_remaining() > 0` → 直接返回 | 限速期间任何请求都是火上浇油 |
| 中途遇限速立刻停 | 循环里每轮检查 | 别等跑完 16 个才发现被限速 |
| 总时间预算 | 150 秒 | 别一直占着后台线程 |

### 5.5 节流与去重

```python
_last_run = 0.0

def start_async(tasks, force=False) -> bool:
    global _last_run
    if _running:
        return False
    if not force and (time.time() - _last_run) < MIN_INTERVAL_SEC:
        return False                    #  10 分钟内不重复预取
    _last_run = time.time()
    threading.Thread(target=prefetch_all, args=(tasks,), daemon=True).start()
    return True
```

### 5.6 实测效果

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 点开详情（首次） | 1860 ms | 1500 ms（纯网络，无法再降） |
| **点开时立即有内容** | 无（只有转圈） | **168 ms 显示已知信息** |
| 已预取的任务 | — | **0.5 ~ 1 ms** |
| 缓存命中率 | — | **17/20 ~ 20/20** |
| 20 个待办平均点开 | 1860 ms | **154 ms** |

**预取本身耗时**：16 个任务 **57 秒**，在后台完成。

### 5.7  前端也要配合：骨架屏而不是转圈

即使有预取，**第一次遇到新任务**时还是要等。
这时前端应该**立刻显示已经知道的信息**：

```
点击卡片
  ↓ 立即（< 200ms）
显示：标题、课程、类型、截止日期、成绩

     附件和评语留成骨架条占位
```

## 六、增量快照 diff：日报的生成机制

### 6.1  核心设计：不做后台定时任务

**Win 版刻意不做「后台定时器」**，原因是：

> 应用不是 24 小时常驻的（用户会关掉）。
> 用定时任务会**丢数据** —— 关机期间的那天就永远没有日报了。

**改用「按日期归档的纯函数」**：

```python
def ensure_today(data) -> dict | None:
    """三个条件都满足才生成：
       ① 今天是工作日（周一~周五）
       ② 已过 21:00
       ③ 今天还没生成过
    """
    now = datetime.now()
    if now.weekday() not in WEEKDAYS:        # {0,1,2,3,4}
        return None
    if now.hour < DIGEST_HOUR:               # 21
        return None
    today = now.strftime("%Y-%m-%d")
    if has_digest(today):
        return None

    d = build(data, today)
    _save(d)
    return d
```

**这样「电脑整天没开」也没关系** —— 开着的时候自动补上当前的这天。
（不补历史：历史无法重建，硬补只会出空日报。）

### 6.2  顺序很重要（很容易写反）

```
抓取完成
  ① 先用「上次快照」做 diff → 生成日报
  ② 再把本次数据存为「上次快照」
```

```python
# pipeline._run_refresh_locked() 末尾
digest.ensure_today(snapshot)      # ① 先 diff
digest.save_snapshot(snapshot)     # ② 再存档
```

**顺序反了的话，diff 永远是空的**（拿自己跟自己比）。

### 6.3 任务的稳定标识

```python
def _task_key(t) -> str:
    """用于跨快照比对 —— 必须是**稳定**的

     优先用 core_tasks 里的数字 id（最稳定）
     退回「课程名 + 标题」
     绝不用「行号」之类会变的东西
    """
    m = re.search(r"/core_tasks/(\d+)", t.url or "")
    if m:
        return f"tid:{m.group(1)}"
    return f"t:{t.course}|{t.title}"
```

### 6.4 diff 三类变化

```python
def _diff(prev: dict | None, cur: dict) -> dict:
    if prev is None:
        return {"first_run": True, "new_tasks": [], "new_grades": [], "newly_done": []}

    pt = {_task_key(t): t for t in prev.get("tasks", [])}
    result = {"new_tasks": [], "new_grades": [], "newly_done": []}

    for t in cur.get("tasks", []):
        k = _task_key(t)
        old = pt.get(k)
        if old is None:
            result["new_tasks"].append(t)          # ① 新增作业
            continue
        if _has_score(t) and not _has_score(old):
            result["new_grades"].append(t)         # ② 新出成绩
        if t.completed and not old.get("completed"):
            result["newly_done"].append(t)         # ③ 新完成
    return result
```

**另加两个提醒组**：今天到期 / 已逾期。

### 6.5 Swift 等价实现

```swift
func diff(prev: Snapshot?, cur: Snapshot) -> Digest? {
    guard let prev else { return nil }

    var newTasks: [Task] = []
    var newGrades: [Task] = []
    var newlyDone: [Task] = []

    let prevByKey = Dictionary(uniqueKeysWithValues: prev.tasks.map { (taskKey($0), $0) })

    for t in cur.tasks {
        guard let old = prevByKey[taskKey(t)] else {
            newTasks.append(t); continue
        }
        if t.hasScore && !old.hasScore { newGrades.append(t) }
        if t.completed && !old.completed { newlyDone.append(t) }
    }
    return Digest(date: today, newTasks: newTasks,
                  newGrades: newGrades, newlyDone: newlyDone, ...)
}
```

### 6.6 总 GPA：简单平均（用户明确指定）

```python
def _overall_gpa(courses) -> float | None:
    """ 简单平均，**不做加权**（用户明确要求）

    只统计「有分数」的课程 —— 没出分的课程不计入（不是按 0 算）
    """
    vals = [g for c in courses if (g := gpa_of(c.mean_percent)) is not None]
    return sum(vals) / len(vals) if vals else None
```

### 7.3  官方 GPA 的严格识别

**不能看到「GPA 3.8」就当官方总 GPA** ——
可能是「某次作业 3.8/4」。

```python
_GPA_ROW_RE = re.compile(r"(?:Cumulative\s+GPA|Overall\s+GPA|累计\s*GPA|平均绩点|总\s*GPA)"
    r"\s*[:：]?\s*(\d{1,2}(?:\.\d+)?)\s*/\s*(\d{1,2}(?:\.\d+)?)",
    re.I)

def parse_official_gpa(soup) -> dict | None:
    """ 必须同时满足：
       ① 有明确的标签词（Cumulative/Overall/累计/总）
       ② 带分母（3.8/4.0）
       ③ 分子 ≤ 分母
       ④ 分母 ≤ 10（排除 100 分制被误认）
    """
    for m in _GPA_ROW_RE.finditer(soup.get_text()):
        val, scale = float(m.group(1)), float(m.group(2))
        if scale <= 0 or scale > 10:   continue    # ④
        if val > scale:                 continue    # ③
        return {"value": val, "scale": scale, "label": m.group(0).strip()}
    return None
```

**11 个用例全过**，拒绝：分子>分母 / 分母为 0 / 分母>10 / 无分母 / 裸 GPA。

所以界面显示的是「**GPA（估算）3.52**」——

### 8.2 四层校验

```python
ALLOWED_HOSTS = ("managebac.cn", "managebac.com", "seiue.com",
                 "amazonaws.com.cn", "amazonaws.com")

DANGEROUS_WORDS = ("logout", "sign_out", "signout", "sign_off", "exit",
    "delete", "destroy", "remove", "drop", "purge",
    "upload", "import", "edit", "update", "new", "create", "add",
    "reset", "revoke", "unsubscribe", "admin", "submit",
)

_ALLOWED_QUERY = {"term", "page", "academic_year", "year", "view",
                  "filter", "cid", "fid", "start_time", "end_time", "expand"}


def check(url: str, *, allow_local: bool = True) -> tuple[bool, str]:
    # ① 协议：只允许 http / https
    if scheme not in ("http", "https"):
        return False, "不支持的协议"

    # ② 域名：精确匹配或子域（ 防 "managebac.cn.evil.com" 伪装）
    if not _host_ok(host):
        return False, "不是受信任的站点"

    # ③ 危险路径：logout / delete / upload ... 一律拦截
    low = path.lower()
    for w in DANGEROUS_WORDS:
        if _has_word(low, w):
            return False, f"链接含危险操作（{w}）"

    # ④ 敏感参数：token / sign / auth / key ... 拒绝
    for k in qs.keys():
        if k.lower() not in _ALLOWED_QUERY:
            return False, f"链接含未知参数（{k}）"

    return True, ""
```

### 8.3  `_host_ok` 的写法很关键

```python
def _host_ok(host: str) -> bool:
    host = (host or "").lower()
    for allowed in ALLOWED_HOSTS:
        if host == allowed:                 # 精确
            return True
        if host.endswith("." + allowed):    #  必须是「点 + 域名」
            return True
    return False
```

**为什么要写成 `"." + allowed`**：
```
host = "managebac.cn.evil.com"
host.endswith("managebac.cn")        → False （这个写法是对的，因为是 .evil.com 结尾）
host = "xmanagebac.cn"
host.endswith("managebac.cn")        → True  （错误！）
host.endswith(".managebac.cn")       → False （加了点就对了）
```

** 必须用 `"." + allowed` 而不是 `allowed`**，
否则 `evilmanagebac.cn` 这种会被误判为安全。

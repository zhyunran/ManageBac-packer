## 1. 整体思路

**目标**：从 `https://<学校>.managebac.cn` 抓下学生的待办任务、成绩、课表、课程资料。

**两条路线对比**（实测数据）：

| 路线 | 耗时 | 稳定性 | 复杂度 |
|---|---|---|---|
| 浏览器自动化（Playwright / CDP） | 98 秒 | 差（浏览器会崩、会卡） | 高 |
| **纯 HTTP 请求** | **20 秒** | 好 | **低** |

**结论：能用 HTTP 就别用浏览器。**

原因：
- 学校网站（ManageBac）**就是普通表单登录**，没有复杂的 JS 加密
- 登录后所有页面都是**服务端渲染的 HTML**，直接 GET 就能拿到完整内容
- 纯 HTTP 不需要启动浏览器，也就没有「窗口未响应」「进程卡死」这类问题

> [注意] 什么时候**必须**用浏览器？
> - 网站是 SPA（React/Vue），HTML 里没有数据，要等 JS 执行完才有
> - 登录有 JS 加密签名、滑块验证、或者设备指纹校验
> - 本站的**课表**就是 SPA，所以那一部分另想办法（见 `schedule.py`）

## 2. 第一步：怎么登录进去

### 2.1 先搞清楚「登录表单长什么样」

打开浏览器的开发者工具（F12）→ Network 标签 → 勾选 `Preserve log`，
然后在登录页输入账号密码并提交，观察发生了什么：

```
POST https://<学校>.managebac.cn/sessions
Content-Type: application/x-www-form-urlencoded

authenticity_token=<一长串>&
login=<你的账号>&
password=<你的密码>&
remember_me=1&
commit=Sign in
```

关键点：
- 这是**普通的表单提交**（`x-www-form-urlencoded`），不是 JSON
- 有一个 `authenticity_token` —— Rails 框架的 CSRF 防护，**必须从登录页 HTML 里挖出来**
- `remember_me=1` 会下发**持久 Cookie**（关键！见 2.3）

### 2.2 完整登录代码

看 `httpclient.py` 的 `login()`。核心逻辑：

```python
import urllib.request, urllib.parse, http.cookiejar, re
from bs4 import BeautifulSoup

# ── ① 建立会话（自带 Cookie 罐）──
jar = http.cookiejar.CookieJar()

#  关键技巧：禁止自动跟随 302 跳转
#   因为「跳转」本身就是「登录成功」的信号，我们要能观察到它
class NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None

opener = urllib.request.build_opener(urllib.request.HTTPCookieProcessor(jar),
    NoRedirect(),                      # ← 关键
)

# ── ② 先 GET 登录页，挖出 authenticity_token ──
html = opener.open("https://xxx.managebac.cn/login").read().decode("utf-8")
soup = BeautifulSoup(html, "html.parser")
token = soup.select_one("input[name='authenticity_token']")["value"]
#          ↑ 也可以直接用正则：re.search(r'name="authenticity_token"\s+value="([^"]+)"', html)
#            但用 BeautifulSoup 更稳（属性顺序可能变）

# ── ③ POST 提交 ──
data = urllib.parse.urlencode({
    "authenticity_token": token,
    "login": "账号",
    "password": "密码",
    "remember_me": "1",                #  一定要勾，否则 Cookie 是会话级
    "commit": "Sign in",
}).encode()

req = urllib.request.Request("https://xxx.managebac.cn/sessions",
    data=data,
    headers={
        "Content-Type": "application/x-www-form-urlencoded",
        #  必须伪装成真浏览器，有些站点会检查 Referer / UA
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                      "AppleWebKit/537.36 (KHTML, like Gecko) "
                      "Chrome/120.0 Safari/537.36",
        "Referer": "https://xxx.managebac.cn/login",
    },
)

# 关掉自动跳转后，成功时会抛 HTTPError(302)
try:
    resp = opener.open(req)
    code = resp.status
except urllib.error.HTTPError as e:
    code = e.code                     # 拿到 302

# ── ④ 判断成功：看状态码 + Cookie ──
session_cookie = next((c for c in jar if c.name == "_managebac_session"), None)
ok = (code == 302) and (session_cookie is not None)
```

### 2.3  为什么一定要勾 `remember_me`

实测结论：

| Cookie 类型 | 跨浏览器重开能保留吗 |
|---|---|
| **持久 Cookie**（有 `Max-Age` / `expires`） | [OK] 能 |
| **会话 Cookie**（没有 `Max-Age`） | [X] 不能，关掉浏览器就没了 |

登录时勾选「Remember me for 30 days」→ 服务端下发**带 `expires` 的 Cookie**
→ 实测有效期约 **30 天**。

这意味着：**登录一次，一个月内都不用再登**。程序只要把 Cookie 存到文件，
下次启动直接装载就行 —— 这就是「打开即有内容」的关键。

```python
# 保存（注意用原子写，避免写到一半断电变成坏文件）
cookies = [{
    "name": c.name, "value": c.value,
    "domain": c.domain, "path": c.path,
    "expires": c.expires,             # ← 这个字段决定能不能持久化
} for c in jar]

tmp = path.with_suffix(".tmp")
tmp.write_text(json.dumps(cookies), encoding="utf-8")
tmp.replace(path)                     # 原子替换

# 下次启动：装载
for c in json.loads(path.read_text(encoding="utf-8")):
    jar.set_cookie(http.cookiejar.Cookie(version=0, name=c["name"], value=c["value"],
        port=None, port_specified=False,
        domain=c["domain"], domain_specified=True, domain_initial_dot=False,
        path=c["path"], path_specified=True,
        secure=True, expires=c["expires"],
        discard=False, comment=None, comment_url=None, rest={},
    ))
```

### 2.4  血泪教训：账号写错会「锁号」

实际踩过的坑：账号域名漏了一个词（`your-school.com` vs `xxxid.com`），
结果 —— 表单填得完全正确、POST 返回 **200**、**不下发任何 Cookie**、
页面上**看不到任何错误提示**、2 秒后跳回 `/login`。

真相：**账号因为连续 5 次登录失败，被服务端临时锁定了。**

**错误提示藏得很深**，不在常见的 `.login-flash` 里，而在：
```html
<div class="alert alert-dismissible alert-inline alert-danger" role="alert">
  <p class="alert-heading h6">Error.</p>
  <div class="alert-content">If your account exists it has been temporarily
  locked due to 5 consecutive failed login attempts. ...</div>
</div>
```

**所以**：
1. **绝不盲目重试登录** —— 每次失败都会**重置锁定计时器**
2. 登录脚本必须识别 `temporarily locked` / `Invalid Email or password`
   并**立即停止重试**，把原因告诉用户
3. 判断方法：对「干净页面」和「提交后页面」做 diff ——
   干净页面里 `temporarily locked` 出现 0 次，提交后 1 次 → 是真错误
   （**不要只看关键词存在就下结论**，页面模板里可能本来就有）

## 3. 第二步：怎么确认登录成功了

**不要靠猜**。三个信号任一即可确认：

| 信号 | 说明 |
|---|---|
| **POST `/sessions` 返回 302** | 最可靠。302 = 服务端让你跳转到首页 = 凭据正确 |
| **拿到了 `_managebac_session` Cookie** | 拿到就说明会话建立了 |
| **GET `/student/home` 返回 200 + 大页面** | 实测 476 KB，含 9 个课程链接 |

对应的「失效」信号：

| 现象 | 含义 | 该怎么办 |
|---|---|---|
| GET 页面被 302 跳到 `/login` | 会话过期 | 重新登录 |
| GET 返回 **429** | **被限速了**（不是登录失效！） | **等待**，绝不能重新登录 |
| GET 返回 401 | 未授权 | 重新登录 |

** 最容易犯的错：把 429 当成 «登录失效» → 去重新登录 → 越试越糟。**

## 4. 第三步：怎么找到「每一门课」

登录后 GET 首页 `https://<学校>.managebac.cn/student/home`，
页面里有全部课程的链接。结构：

```html
<a href="/student/classes/1234567/core_tasks">IDS Big History</a>
<a href="/student/classes/2345678/core_tasks">Physics</a>
...
```

解析代码（看 `scraper.py` 的 `parse_courses()`）：

```python
soup = BeautifulSoup(html, "html.parser")

courses = []
seen = set()
for a in soup.select("a[href*='/student/classes/']"):
    href = a.get("href", "")
    m = re.search(r"/student/classes/(\d+)", href)
    if not m:
        continue
    cid = m.group(1)
    if cid in seen:                   #  去重！页面里同一个课程会有多个链接
        continue
    seen.add(cid)

    name = a.get_text(" ", strip=True)
    if not name:                      # 有些链接是图标/按钮，没有文字
        continue

    courses.append({
        "class_id": cid,
        "name": name,
        "url": urljoin(BASE_URL, href),
    })
```

**要点**：
- 用 `a[href*='/student/classes/']` 这种**属性包含选择器**，比记 class 名稳
- **一定要去重** —— 一个课程在首页可能出现好几次（导航、侧栏、卡片）
- URL 里的**数字 ID** 是后续一切请求的基础，务必正确提取

以一门课为例（`cid = 1234567`）：

### 5.1 要请求哪几个页面


### 5.2  最容易踩的坑：成绩单元格是「兄弟节点」

任务卡片和它的成绩**不是父子关系**，而是**兄弟关系**！

```html
<!-- 错误理解：成绩在卡片里面 -->
<div class="fusion-card-item short-assignment">
  <div class="h4 title">作业名</div>
  <div class="assessment-cell">A 100 / 100 pts</div>   ←  实际不长这样
</div>

<!--  实际结构：成绩是卡片的兄弟 -->
<div class="fusion-card-item short-assignment">
  <div class="h4 title">作业名</div>
  ...
</div>
<div class="assessment-cell">A 100 / 100 pts</div>     ←  平行在下一行
```

**早期版本的 bug**：只从卡片往上找父级、再往下找成绩
→ **永远读不到成绩** → 已完成的任务全被当成待办。

**修复**：写一个 `_find_sibling_cell(card)`，从卡片往后找同级的
`.assessment-cell`：

```python
def _find_sibling_cell(card):
    """成绩单元格是卡片的兄弟节点，不是子节点。

    两种可能的位置都试：
      1. 卡片自身的父节点里，卡片之后的下一个 assessment-cell
      2. 卡片外层容器里的 assessment-cell
    """
    # 先看卡片内部（有些版本确实在里面）
    cell = card.select_one(".assessment-cell")
    if cell:
        return cell

    # 再找兄弟：从卡片往后遍历同级元素
    for sib in card.next_siblings:
        if getattr(sib, "select_one", None):
            cell = sib.select_one(".assessment-cell")
            if cell:
                return cell
            # 也可能兄弟本身就是那个单元格
            cls = sib.get("class") or []
            if "assessment-cell" in cls:
                return sib

    # 最后看父容器（兜底）
    parent = card.parent
    if parent:
        cells = parent.select(".assessment-cell")
        # 按顺序对应：第 N 个卡片 ↔ 第 N 个单元格
        cards = parent.select(".fusion-card-item.short-assignment")
        if len(cells) == len(cards):
            try:
                idx = cards.index(card)
                return cells[idx]
            except ValueError:
                pass
    return None
```

### 5.3 成绩原文长什么样，怎么解析

实测的真实格式：

```
A 100 / 100 pts          ← 字母等级 + 得分/满分
B 82 / 100 pts
D 65 / 100 pts
Not Assessed Yet         ← 还没评分
```

解析规则（`gpa.py` 的 `parse_score()`）：

```python
_NUM    = re.compile(r"-?\d+(?:\.\d+)?")
# 字母等级：前后不能紧邻字母数字，正确处理 +/- 后缀
_LETTER = re.compile(r"(?:^|[^A-Za-z0-9])([A-F])([+-])?(?![A-Za-z0-9])")

def parse_score(raw, max_score=""):
    raw = (raw or "").strip()
    if not raw or re.search(r"not\s+(assessed|submitted|graded)", raw, re.I):
        return None                              # 明确表示「没成绩」

    # ① 优先：得分 / 满分形如 "100 / 100"
    m = re.search(r"(\d+(?:\.\d+)?)\s*/\s*(\d+(?:\.\d+)?)", raw)
    if m:
        num, mx = float(m.group(1)), float(m.group(2))
        return {"score_num": num, "score_max": mx,
                "percent": round(num / mx * 100, 2) if mx else None}

    # ② 字母等级
    m = _LETTER.search(raw)
    if m:
        letter = m.group(1) + (m.group(2) or "")
        return {"level": letter, "percent": LETTER_TO_PERCENT[letter]}

    # ③ 纯数字：可能是百分制，也可能是 IB 1-7 等级
    nums = _NUM.findall(raw)
    if nums:
        v = float(nums[0])
        if v <= 7 and BARE_NUMBER_IS_IB_LEVEL:
            return {"level": str(int(v)), "scale": "ib"}
        return {"percent": v, "scale": "percent"}
    return None
```

**换算表**（按你学校的规定改 `gpa.py` 顶部的常量即可）：

```python
IB_TO_GPA = {7: 4.0, 6: 3.7, 5: 3.3, 4: 3.0, 3: 2.7, 2: 2.3, 1: 1.0}

LETTER_TO_GPA = {"A+": 4.0, "A": 4.0, "A-": 3.7,
                 "B+": 3.3, "B": 3.0, "B-": 2.7,
                 "C+": 2.3, "C": 2.0, "C-": 1.7,
                 "D+": 1.3, "D": 1.0, "D-": 0.7, "F": 0.0}

PERCENT_BANDS = [(93,4.0),(90,3.7),(87,3.3),(83,3.0),(80,2.7),
                 (77,2.3),(73,2.0),(70,1.7),(67,1.3),(63,1.0),
                 (60,0.7),(0,0.0)]        # 从高到低匹配
```

### 5.4 分类权重（各类作业占总评多少）

课程页里有这种结构：

```python
headers = [th.get_text(" ", strip=True).lower() for th in table.select("th")]
```

## 6. 第五步：怎么判断作业「交了没有」

任务卡片上有状态徽章：

```html
<span class="badge-label">Submitted</span>
<span class="badge-label">Pending</span>
<span class="badge-label">Late</span>
```

**业务规则**（用户明确定义）：

> **只要满足「已登记成绩」或「已提交文件」任意一项，
> 就判定为彻底完成，移出所有待办栏目。**

```python
def is_done(task) -> bool:
    if task.submitted or task.graded:
        return True
    # 分数也是「已评分」的证据
    if task.score_num is not None and task.score_max is not None:
        return True
    if task.score and not re.search(r"not\s+assessed", task.score, re.I):
        return True
    # 状态文本兜底
    if re.search(r"已提交|已评分|submitted|graded", task.status, re.I):
        return True
    return False
```

**前端会再算一遍**（不信任后端写好的 `completed` 字段），
这样即使后端某次抓取有偏差，界面显示也是对的。

### 7.3 下载文件

文件直链是 **S3 地址**（`...s3.cn-north-1.amazonaws.com.cn/...`）。

** 关键：必须从 Python 直连 + 带上 Cookie。**
在浏览器里 `fetch()` 会被 **CORS 拦掉**，报 `Failed to fetch`。

```python
def download_direct(url, dest, cookies):
    req = urllib.request.Request(url, headers={
        "User-Agent": UA,
        "Cookie": "; ".join(f"{k}={v}" for k, v in cookies.items()),
    })
    with urllib.request.urlopen(req, timeout=30) as r, open(dest, "wb") as f:
        shutil.copyfileobj(r, f)
```

## 8. 第七步：怎么把它跑快

从 98 秒优化到 20 秒的过程：

| 阶段 | 耗时 | 做法 |
|---|---|---|
| 浏览器自动化 | 98s | Playwright 启动 + 等页面加载 |
| HTTP 串行 | 60s | 去掉浏览器，逐个课程请求 |
| **HTTP 并行** | **20s** | `ThreadPoolExecutor`，每门课一个线程 |

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def _fetch_courses_parallel(courses, workers=3):
    results = {}
    with ThreadPoolExecutor(max_workers=workers) as ex:
        futures = {}
        for c in courses:
            #  每个线程必须有**自己的** session（独立 Cookie 罐）
            #   共享一个 session 会有竞态
            futures[ex.submit(_fetch_one_course, c)] = c
        for fut in as_completed(futures):
            c = futures[fut]
            try:
                results[c.class_id] = fut.result()
            except Exception as e:
                log.warning("课程 %s 抓取失败：%s", c.name, e)
    return results
```

** 为什么 workers=3 而不是 6？**
线程数太高会触发网站限速（返回 429）。实测 6 会稳定触发，
降到 3 之后就没再出问题。**别贪心。**

## 9. 坑：网站限速了怎么办

**症状**：`GET /student/home` 返回 **429**，body 只有 **32 字节**。

```python
if resp.status == 429:
    #  关键：标记「被限速」，绝不能当成「登录失效」
    self.rate_limited = True
    raise RateLimited()
```

**全局冷却机制**（`data/rate_limit.json` 记时间戳）：

```python
COOLDOWN_SEC = 240          # 被限速后，240 秒内不再请求

def set_cooldown():
    path.write_text(json.dumps({"until": time.time() + COOLDOWN_SEC}))

def cooldown_remaining() -> float:
    try:
        until = json.loads(path.read_text()).get("until", 0)
        return max(0.0, until - time.time())
    except Exception:
        return 0.0
```

**并且在冷却期内的行为**：
- 保留旧缓存，不去请求（避免继续触发）
- **跳过自动登录**（登录请求也算请求）
- 拉长下次刷新时间：`next_run_ts = now + min(cooldown + 5, 300)`

**教训**：
> 任何抓取脚本都要先区分
> `401 / 302→登录页`（要重新登录）
> vs `429`（要**等待**）。
> 后者绝不能触发登录，否则可能累积失败次数 → **锁账号**。

## 10. 坑：怎么看出是「登录失效」还是「被限速」

写一个专门的检测函数，**不要靠 status code 一刀切**：

```python
def check_login(session) -> bool:
    """判断会话还有效吗。返回 True = 有效。"""
    try:
        r = session.get("/student/home")

        # ① 429 = 被限速。保守认为「会话有效」，并且**跳过自动登录**
        if r.status == 429:
            session.rate_limited = True
            log.warning("被限速了（429），本次不做任何登录动作")
            return True

        # ② 302 到 /login = 真的失效了
        if r.status == 302 and "/login" in (r.headers.get("Location") or ""):
            return False

        # ③ 200 且页面里有登录后才有的元素 = 有效
        if r.status == 200 and "student/home" in r.url:
            return True

        return False
    except Exception as e:
        log.warning("检测登录状态失败：%s", e)
        return True          #  网络问题时保守处理，别贸然重新登录
```

##  三条最重要的经验

1. **能用 HTTP 就别用浏览器** —— 快 5 倍、稳得多、代码还更简单。
   先花 10 分钟确认真实请求长什么样（F12 Network），能省掉几天折腾。

2. **区分「登录失效」和「被限速」** ——
   把 429 当成登录失效会导致无限重试 → 账号被锁。

3. **登录失败绝不盲目重试** —— 每次失败都重置服务端的锁定计时器。
   一定要能读出服务端的错误提示（哪怕它藏在很深的 div 里）。

##  SPA 站点怎么办（以课表为例）

课表网站是 React SPA，HTML 里**没有数据**。这时两条路：

**路线 A（推荐）：直接调它的后端 API**

打开 F12 → Network → 筛选 `Fetch/XHR`，找返回 JSON 的请求：

```
GET https://api.xxx.com/chalk/calendar/personals/{id}/events
    ?start_time=2026-09-18 00:00:00&end_time=2026-09-18 23:59:59
    &expand=address,initiators
Authorization: Bearer eyJhbGc...      ← 从 localStorage 里读出来的 JWT
```

然后 Python 里直接用：

```python
req = urllib.request.Request(api_url, headers={
    "Authorization": f"Bearer {token}",
    "User-Agent": UA,
})
data = json.loads(urllib.request.urlopen(req).read().decode("utf-8"))
```

**怎么拿到 token**：在浏览器 Console 里执行
```js
JSON.parse(localStorage.getItem('persist:root')).session
// → 里面找 oAuthToken.accessToken
```

** 注意 CORS**：浏览器里 `fetch()` 这个 API 会被 CORS 拦掉，
但 **Python 直连没有 CORS 限制**（同源策略只在浏览器里生效）。

**路线 B（不推荐）：用 Playwright 等页面渲染完再读 DOM**
慢、脆、而且 SPA 的 DOM 结构容易变。

> 本项目课表的 OAuth 想纯 HTTP 登录失败了
> （`POST /chalk/oauth/tokens` 报服务端 500）。
> 所以折中：**用浏览器登录一次拿 token，之后把 token 存下来纯 HTTP 用**。
> 这个「一次手动 + 之后自动」的混合方案往往最实用。
